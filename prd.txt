PROJECT PRD / BUILD PROMPT
==========================

PROJECT NAME
Citation Verifier

PROJECT TYPE
Research integrity / academic verification platform

PRIMARY GOAL
Build a production-style web application that accepts a research paper PDF and verifies the citations used inside the paper using real academic metadata sources and local NLP models.

The system must not behave like a generic “AI citation checker”. It must be deterministic where possible, transparent in how each result is produced, and must clearly separate:
1. Reference existence verification
2. Metadata correctness
3. Citation-context relevance
4. Citation quality
5. Potential overclaiming / unsupported citation usage

This is intended to be a serious, M.Tech-level engineering project, not a hackathon mockup.

The application must use:
- Python
- FastAPI
- React
- JavaScript
- Local NLP models
- Sentence-BERT or equivalent local sentence embedding model
- FAISS or equivalent local vector search
- PyMuPDF for PDF text extraction
- Crossref API
- Semantic Scholar API
- Local file storage only
- JSON / TXT / local cache files
- No database
- No OpenAI API
- No Gemini API
- No Claude API
- No paid AI API
- No mock verification data
- No fake metrics
- No randomly generated “confidence scores”

The frontend must use:
- White background
- Light theme only
- No dark mode
- No gradient-heavy “AI” style
- No purple neon, blue-purple gradient, glowing cards, glassmorphism, oversized rounded cards, floating blobs, chatbot-like UI, sparkle icons, or generic AI-generated SaaS visual language
- The design should look like a serious academic / research productivity tool
- Visual inspiration should be closer to Zotero, Semantic Scholar, Google Scholar, Overleaf, academic dashboards, or modern research tooling

======================================================================
1. PROBLEM STATEMENT
======================================================================

Research papers often contain citation problems such as:
- References that do not exist
- Incorrect title, author, DOI, venue, year, or publication metadata
- In-text citations that point to the wrong reference
- References that exist but are irrelevant to the claim they are attached to
- Citations that weakly support a statement
- Citations used to exaggerate or overstate findings
- Excessive reliance on a small subset of references
- Old references used when newer research exists
- Duplicate references
- Missing DOI or incomplete metadata
- AI-hallucinated references created by generative tools

The system should help a student, researcher, reviewer, or faculty member inspect citation reliability in a transparent way.

The system is NOT a medical or legal decision-making system.
It is an academic research support tool.

======================================================================
2. CORE PRODUCT PRINCIPLES
======================================================================

The system must follow these principles:

1. REAL DATA ONLY
Every citation verification must be based on real extracted PDF text and real external academic metadata.

Never populate the UI with placeholder papers, made-up authors, fake DOIs, artificial citation counts, or dummy relevance values.

2. TRACEABILITY
For every result, the user must be able to understand:
- what was extracted
- what API result was matched
- what similarity score was computed
- how the final status was derived

3. LOCAL NLP
All semantic analysis should be performed locally using a downloaded transformer / sentence embedding model.

4. NO GENERATIVE AI DEPENDENCY
Do not depend on an external LLM.

5. NO DATABASE
Use local filesystem storage and in-memory runtime objects.

6. FAIL GRACEFULLY
If Semantic Scholar or Crossref does not return a result, say:
- "No verified match found"
instead of inventing a result.

7. DISTINGUISH FACT FROM HEURISTIC
For example:
- “DOI matched Crossref” = verified fact
- “Citation context relevance: 0.73 cosine similarity” = computed heuristic
- “Potential overclaim” = heuristic flag, not a factual accusation

8. ACADEMIC VISUAL STYLE
The website must look trustworthy, restrained, readable, and deliberately designed.

======================================================================
4. FIVE CORE USPs
======================================================================

USP 1: CONTEXT-AWARE CITATION VALIDATION

The system should not stop at checking whether a cited paper exists.

For each in-text citation:
- extract the sentence containing the citation
- optionally include one sentence before and after
- identify the matching reference from the bibliography
- retrieve metadata and abstract of that reference
- embed the citation context
- embed the cited paper abstract
- compute semantic similarity

The system should output:
- Strongly supported
- Moderately supported
- Weakly related
- Likely unrelated
- Unable to evaluate

Do not use arbitrary labels without showing the numerical similarity score.

The thresholds must be configurable in the backend.

Example starting thresholds:
- >= 0.78: Strongly related
- 0.62–0.779: Moderately related
- 0.45–0.619: Weakly related
- < 0.45: Likely unrelated

These are heuristic starting values and must be clearly identified as such.

USP 2: FAKE / HALLUCINATED REFERENCE DETECTION

For each bibliography entry:
- normalize title
- extract author names if possible
- extract publication year
- extract DOI if present
- search Crossref
- search Semantic Scholar
- compare returned title to extracted title using fuzzy matching
- compare year
- compare authors
- compare DOI

Classify reference existence into:
- Verified exact match
- Verified probable match
- Metadata mismatch
- No verified match found
- API unavailable

The application must never call an unverified reference “fake” with certainty.
Use wording such as:
- "No verified record found"
- "Potentially hallucinated or malformed reference"

USP 3: CITATION QUALITY SCORE

Each citation/reference may receive a transparent quality score.

The score must be based on actual measurable features such as:
- metadata match quality
- citation-context similarity
- publication recency
- citation count, only if a trusted API supplies it
- DOI presence
- author/year consistency

The scoring system must be documented.

Example scoring structure:
- 35 points: metadata verification
- 35 points: semantic relevance
- 10 points: year match
- 10 points: author match
- 10 points: source metadata completeness

Do NOT create fake citation counts or impact scores.

Do NOT imply that citation count equals scientific truth.

USP 4: CITATION NETWORK / RELATIONSHIP VISUALIZATION

Create a visualization of:
- current uploaded paper at the center
- references as linked nodes
- optional edges among cited papers when available

At minimum:
- one node = uploaded paper
- one node per extracted verified reference
- edge = paper cites reference

Node state can represent:
- verified
- uncertain
- metadata mismatch
- unverified

The visualization must be based on the actual processed paper.

Do not generate decorative graph data.

USP 5: POTENTIAL OVERCLAIM / CLAIM-STRENGTH MISMATCH DETECTION

Without an LLM, implement this as a transparent heuristic.

The system should inspect citation sentences for strong claim terms such as:
- proves
- always
- completely
- guarantees
- establishes
- demonstrates conclusively
- significantly outperforms
- dramatically improves
- eliminates
- universally
- definitive

Then compare:
- citation-context semantic similarity
- abstract similarity
- lexical overlap with abstract
- presence or absence of similar strong claim language in the abstract

Flag as:
- No concern detected
- Review recommended
- Potential overclaim

This is only a heuristic and must be presented as such.

Never state that an author is dishonest or that a citation is fraudulent.

======================================================================
7. END-TO-END WORKFLOW
======================================================================

STEP 1: Upload

User uploads:
- one PDF

Validation:
- must be PDF
- reject unsupported file type
- configurable max file size
- reject zero-byte files
- sanitize filename
- compute SHA-256 hash

If same paper hash has already been processed:
- allow reusing cached result
- allow manual re-run

STEP 2: PDF Text Extraction

Use PyMuPDF.

Extract:
- full text
- page-level text
- page numbers
- probable bibliography section
- probable in-text citations

Save:
uploads/<hash>.pdf
data/<hash>_text.txt

Do not overwrite another file silently.

STEP 3: Detect Reference Section

Try headings:
- References
- Bibliography
- Works Cited
- Literature Cited

Use case-insensitive detection.

If not found:
- try bottom portion of document heuristics
- show warning in UI

STEP 4: Parse Bibliography

Support initial formats:
- IEEE numeric references
- APA-like references
- numbered plain references

Extract per reference:
- local reference id
- raw reference text
- title
- authors
- year
- venue
- volume
- issue
- pages
- DOI
- URL if present

Parsing quality may vary.
Always preserve raw reference text.

STEP 5: Parse In-Text Citations

Support:
- [1]
- [2, 4]
- [3–5]
- (Smith, 2022)
- Smith et al. (2022)

Each occurrence should store:
- citation marker
- page number if available
- sentence
- previous sentence
- next sentence
- mapped bibliography reference ids
- extraction confidence

STEP 6: Verify References

For each reference:

A. If DOI exists:
- query Crossref DOI
- query Semantic Scholar DOI if supported
- compare metadata

B. If no DOI:
- search title
- normalize punctuation/case
- compare title similarity
- compare first author
- compare year

Store:
- API source
- matched paper title
- matched authors
- year
- DOI
- venue
- URL
- abstract when available
- citation count when available
- raw API confidence/score if supplied
- local fuzzy-match score

STEP 7: Build Match Confidence

Example:
title similarity: 50%
author match: 20%
year match: 15%
DOI exact match: 15%

If DOI exact matches, verification should be considered very strong.

Do not rely only on fuzzy title similarity.

STEP 8: Semantic Citation Validation

For each in-text citation with verified metadata:

Construct citation context:
previous sentence + target sentence + next sentence

Retrieve:
- abstract
- title
- optional external metadata

Create embedding:
- context
- abstract
- optionally title + abstract

Normalize vectors.

Use cosine similarity.

FAISS can:
- index all reference abstract vectors
- identify which references are semantically nearest to a citation context
- compare expected reference to nearest candidates

This adds an advanced feature:
"Was the cited paper actually the most semantically relevant reference among the bibliography?"

Store:
- expected citation similarity
- rank among all reference vectors
- top 3 similar references
- classification

STEP 9: Quality Scoring

Produce:
- Reference Verification Score
- Context Relevance Score
- Overall Citation Confidence Score

Do not combine them in a way that hides their components.

The UI must show the breakdown.

STEP 10: Overclaim Heuristic

Detect strong assertion words in citation sentence.

Compare:
- strength indicator
- abstract wording
- similarity score

Flag only when appropriate.

STEP 11: Summary

Show real totals:
- Total references detected
- Verified exact
- Verified probable
- Metadata mismatch
- Unverified
- Total in-text citation occurrences
- Strong relevance
- Moderate relevance
- Weak relevance
- Potentially unrelated
- Potential overclaim flags

STEP 12: Export

Allow:
- Download analysis JSON
- Download human-readable TXT report

Optional:
- CSV export

18. NLP PIPELINE
======================================================================

Load local embedding model once at application startup.

Do not reload model for every request.

Pipeline:
1. normalize text
2. sentence split
3. compose citation context
4. encode contexts in batch
5. encode abstracts in batch
6. normalize embeddings
7. build FAISS index
8. compute search results

Use batching for performance.

Keep raw cosine similarity.

Do not transform similarity to fake percentages unless clearly stated.

Preferred display:
"Semantic similarity: 0.74"

Optional:
"74/100 relevance index"
only if explained as a normalized heuristic.

======================================================================
19. FAISS USAGE
======================================================================

For a paper with N verified references:

- encode N reference texts
- build IndexFlatIP after vector normalization
- encode each citation context
- retrieve top-k closest references

For each citation:
store:
- cited reference rank
- cited reference similarity
- top 3 references
- gap between top result and cited result

Interesting heuristic:
if cited reference ranks very low and another reference strongly outranks it, mark:
"Review citation selection"

Do not label as incorrect automatically.

======================================================================
21. SCORING SYSTEM
======================================================================

Keep scores transparent.

REFERENCE VERIFICATION SCORE / 100

Example:
DOI exact match: 30
Title match: 35
Author match: 20
Year match: 15

If DOI absent:
redistribute weight across title/author/year.

CONTEXT RELEVANCE SCORE
Use cosine similarity separately.

Do not hide raw value.

OVERALL SCORE
If required:
- metadata: 55%
- semantic relevance: 45%

Overall score must not be used where no semantic information exists.

If abstract missing:
show:
"Overall score unavailable"
or
"Metadata-only score"

Do not pretend semantic verification occurred.

11. Use proper error handling.
12. Preserve raw reference text.
13. Cache external API results.
14. Expose scoring components to frontend.
15. Do not silently classify unavailable data as negative.
16. Use "unknown" or "unavailable" states.
17. Never claim semantic similarity proves factual correctness.
18. Never label a paper fraudulent based only on heuristics.
19. Keep the frontend functional before decorative.
20. Every graph, number, score, and status shown to the user must originate from actual analysis output.

FINAL PRODUCT POSITIONING

Citation Verifier is a transparent research-integrity platform that verifies whether academic references exist, compares extracted metadata with trusted scholarly sources, measures whether citations are semantically related to the claims in which they are used, and highlights references that require human review.
The key engineering differentiator is that semantic verification runs locally using sentence embeddings and FAISS, while publication existence and metadata are checked against real scholarly services.
The product must feel like serious academic software rather than a generic AI wrapper.
